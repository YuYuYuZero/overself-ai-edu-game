# 美术与 UI 设计：漫画幻灯片式的视觉小说

> 本文说明画面怎么呈现：舞台怎么分层、人物怎么设计、旁白和对白怎么区分、每个交互放在哪里。
> 实现文件：`demo/art.js`（立绘与背景）、`demo/vn.js`（舞台）、`demo/style.css`（「视觉小说舞台」一节）。
> 预览所有立绘和背景：浏览器打开 `tools/art-preview.html`。常用参数：
> - `?m=chars`：全部人物
> - `?m=expr&id=xiaoman`：某个人物的全部表情
> - `?m=bg`：全部背景

---

## 1. 为什么从"聊天框"改成"舞台"

v1 的 demo 是聊天气泡流，像在看一段微信记录。问题有三个：

1. **没有人。** 共情要从脸开始。玩家看不到妈妈攥床单的手、林可低头的样子，"信号捕捉"就只剩文字游戏。
2. **没有空间。** 医院走廊、凌晨的病房、放学后空掉的教室，这些地方自己就带着情绪。只写一行"凌晨 3:10 · 走廊"，玩家进不去。
3. **旁白和对白混在一起。** 叙述、心声、台词在同一种气泡里，读起来累，戏剧性也被冲淡。

所以 v2 改成**漫画幻灯片式的视觉小说**：一张背景、一到三个人物、底部一个对话框，一页一页往下翻。

## 2. 舞台分层（从下到上）

```
┌──────────────────────────────────────────────┐
│ ▔▔▔▔ 全局进度条（每章一段，点击打开目录）▔▔▔▔ │ z 32
│ HUD：存档退出 · ☰目录 % · 章名 · 视角 · 回看 · 数值条 │ z 30
│ [地点牌]                    [漫画旁白框]        │ z 17/18
│                [信号 / 解码卡]                  │ z 25
│        ┌─立绘─┐   ┌─立绘─┐   ┌─立绘─┐          │ z 5
│        │ 视角 │   │说话者│   │ 在场 │  [手机] │ z 16
│ ┌─[名牌]────────────────────────────────────┐ │
│ │ 对话框：台词 / 心声                     ▼ │ │ z 20
│ └───────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
背景层（两张交替淡入淡出，z 0）
```

| 层 | 规则 |
|---|---|
| **背景** | 每个 `scene` 节点可以换背景。两张背景交替，0.9 秒淡入淡出。场景底部压暗，保证字看得清 |
| **立绘** | 最多同时 3 人。视角人物固定在最左边。正在说话的人亮起来、略放大，其他人压暗（brightness .55）。说话时嘴巴开合，平时每 4.6 秒眨一次眼，身体有轻微的呼吸起伏 |
| **电话中的人** | 立绘周围加一圈蓝色光晕，右上角有 📞，名牌也带 📞。观众一眼就知道"他不在现场" |
| **对话框** | 底部半透明白框，左上角是名牌。视角人物的名牌用视角主色（弟弟蓝、姐姐珊瑚）。**心声**换成深紫底、浅紫斜体字，名牌写「林晚（心里）」 |
| **旁白** | 见 §3 |
| **手机** | 家庭群、班群、私聊这类消息不进对话框，而是出现在画面里的一部手机上：头像是人物头部特写，最多同时显示 5 条。看手机的人（视角人物）留在画面里 |
| **交互面板** | 选项悬浮在对话框上方，看得见上一句台词。分类、排序、拼句、身体信号这类大面板，以居中卡片盖住对话框 |
| **进度条与目录** | 顶部细条，每章一段，有镜面的章再分三格；悬停变粗。目录是居中卡片：视角切换（头像）、每章缩略图 + 阶段按钮，当前位置紫色 ▶，玩过的绿色 ✓。手机上「存档退出」「目录」只留图标和百分比，保证顶栏一行放得下 |
| **推进** | 右下角 ▼ 按钮，点舞台空白处也能推进。按钮会轻轻上下浮动 |

## 3. 旁白的三种呈现（用户要求：像看漫画，关键处黑屏白字）

| 种类 | 什么时候用 | 呈现 |
|---|---|---|
| **漫画旁白框** | 绝大多数叙述：动作、细节、环境（"她笑了一下，低头一直搅着那杯已经凉掉的咖啡"） | 左上角米黄色方框，黑色粗边，加漫画式硬阴影，轻微倾斜 -0.6°。**背景和人物始终可见**，旁白时所有立绘压暗，像漫画格子里的说明文字 |
| **地点牌** | 每个场景开头（"03:10 · 医院 6 楼走廊"） | 右上角黑底白字小牌，左边一道视角主色竖条，淡入后一直留在角落 |
| **黑屏白字** `{t:"title"}` | 情绪转折点、时间跳跃、章节收尾（"她走了。还剩三天。""两天后，周五晚上 22:40"） | 全屏纯黑，白字居中，字间距加大。停留时长按字数算（至少 2.4 秒），然后淡出。整章只用 2～5 次，用多了就不"重"了 |

另外还有两种系统提示：
- **时间提示**：倒带、超时之类（"⏪ 时间倒回到刚才那一刻……"），用深色半透明框。
- **暂停与呼吸**：画面中央的大字（"你停了下来。先停一下。"），同时背景和人物变蓝、变模糊，像沉到水下，和 `mute_dive` 音效配合。

**写旁白的规则**（剧本作者看这里）：
- 写画面，不写结论。✗"她很难过" ✓"她笑了一下，没看你们的眼睛"。情绪交给玩家自己去读，这本身就是 T→F 的练习。
- 一句旁白只放一个镜头。两个镜头就拆成两句，玩家每点一下就是翻一格漫画。
- 关键信号写进旁白，同时做成可捕捉的信号（`sig`）：旁白给所有人看，信号只奖励看见它的人。

## 4. 人物设计

### 4.1 统一画风

- 日系动画半身立绘，平涂 + **赛璐璐式硬阴影**，光从左上方来（v4）：
  - **彩色线稿**：衣服的描边用衣服本色压暗（`shade(主色, -0.62)`），不再统一用深棕线，整体更柔和；头发、皮肤本来就是各自的深色线。
  - **阴影**：右臂整条落在阴影里、左臂只压暗内侧，躯干右侧一条竖向暗面，领口下方一道投影；刘海在额头上投下阴影（原有）。阴影都裁在身体轮廓里（`clipPath bd*`），不会溢出。
  - **轮廓光**：左肩一笔浅色高光，让人物从背景里"立"起来。
  - **头发高光**：头顶一圈锯齿状的"天使环"（下缘一长一短）加两点白色反光，替换原来那条细弧线。
- 五官比例只随年龄变化、年轻角色不画下眼线（v3.1 定下的规则，v4 不动脸）。
- **眉毛画在头发上面**（动画惯例），这样刘海再厚，表情也能读出来。
- 9 种表情：normal / smile / sad / angry / surprise / worry / cry / think / shy。表情由眉毛角度、眼睑高度、视线方向、嘴型、腮红、眼泪、汗滴组合出来。
- 用代码生成 SVG，不用图片文件：离线可用、体积小、表情切换零成本。

## 5. 舞台外的页面

章首、复盘和结局页不在舞台上，但也要有画面。这些页面左上角同样有「存档退出」和「☰ 目录」，顶部同样有进度条：

- **章首**：底图是本章第一个场景的背景，做虚化处理。上面是章名，两个视角人物的头像各配一句"这一章要学会……"。
- **复盘**：技能卡上带人物头像。
- **结局**：两人头像并排。好结局两人都笑，「还没说出口」这档两人都是 sad。
- **首页故事卡**：用故事的封面背景，两位主角站在前面，像一张海报。

## 6. 换成正式插画

接口已经留好，剧情数据一行都不用改：

```js
// 在 art.js 末尾或新文件里登记
ART.IMG["bg:classroom"] = "img/bg/classroom.jpg";          // 1600×900 或更大
ART.IMG["char:xiaoman:smile"] = "img/char/xiaoman_smile.png"; // 透明底，400×800 比例
ART.IMG["char:xiaoman"] = "img/char/xiaoman.png";             // 没登记的表情用这张
```

登记过的就用图片，没登记的继续用 SVG，可以一张一张逐步替换。

**AI 生图的提示词模板**（适用于 Seedream、Midjourney 等）：
- **背景**：`anime background art, {场景描述}, soft lighting, no people, wide shot, 16:9, makoto shinkai style, clean lines`
- **人物**：`anime character sheet, {年龄} {性别} {发型} {服装}, half body, front view, plain white background, {表情}, consistent design, clean lineart`

人物最难的是**同一个人不同表情要长得一样**。建议先出一张定稿立绘，再用"参考图 + 改表情"的方式生成其余 8 种表情，最后统一抠成透明底。

本机的 arkcli（火山方舟 Seedream）登录已过期。要生图需要先运行 `arkcli auth login volc-sso` 重新登录，会产生费用。

## 7. 页面风格（v4「修炼手册」）

产品名是「MBTI 性格修炼手册」，页面就往**一本手册**的感觉去做，同时保留 logo 里 T 蓝 / F 橙两半大脑的双色母题。

| 元素 | 做法 |
|---|---|
| 纸 | 底色 `#f6f1e7`，叠一层 22px 点阵（像手账本的点格纸）；卡片是更白的 `#fffdf8`，1px 纸边线 + 很淡的投影 |
| 墨 | 正文 `#24223a`（偏靛的墨色），次要文字 `#4e4b63` / `#8b8698` |
| 标题 | 宋体（`Songti SC` / `Noto Serif SC`），粗体，像书里的章节标题；正文仍用系统黑体保证易读 |
| 章节序号 | 壹、贰、叁……放在 T 蓝 → 靛紫 → F 橙渐变的小方块里，微微倾斜，像贴在页边的索引签 |
| 印章 | 红色方章「修炼」：首页品牌旁、分享卡右上角；推荐标签也用同一个红 |
| 主按钮 | 首页的「开始 MBTI 测试」用 T 蓝 → 靛紫 → F 橙的渐变，其他按钮跟随当前路线色 |
| 气质组色 | 结果页、分享卡按 NT 紫 / NF 绿 / SJ 蓝 / SP 橙上色（`MBTI.groups`） |

设计变量集中在 `demo/style.css` 开头的 `:root` 和 `miniprogram/app.wxss` 的 `page`，两边名字一致（`--bg --card --ink --brand --t --f --seal --serif …`）。舞台（故事 / 练习关）沿用原来的视觉小说样式，不受影响。

测试页的 7 级量表：左边「同意」绿、右边「不同意」紫，圆圈两端大、中间小；答过的题变淡，自动滚到下一题。

## 8. 分享卡片

结果页「生成分享卡片」→ 一张 750×1200 的竖版海报（2 倍像素），适合发朋友圈、存相册：

```
┌──────────────────────────────┐
│ [logo] MBTI 性格修炼手册   [修炼]│  ← 气质组主色的渐变色块，斜线纹 + 两个浅色圆
│ 我的人格类型                   │
│ ENFP                [人物形象] │  ← 人物站在色块右侧，裁到胸口
│ 灵感四溢的追梦人                 │
│ (理想派 · NF)                  │
│ 「一句话画像」                  │
├──────────────────────────────┤
│ 四个维度          专业版 60 题  │  ← 2×2 双向条，标百分比和清晰度
│ 我的另一面：F 解锁 T · 冷静解题  │  ← 成长建议
│ ------------------------------ │
│ 测出你的 MBTI，体验另一面  [码] │  ← 小程序码（有就画）
└──────────────────────────────┘
```

- **一份绘制代码，两端共用**：`demo/share-card.js` 只用 Canvas 2D 的基础接口（`fillText / arcTo / createLinearGradient / drawImage`），网页版的 `<canvas>` 和小程序的 `canvas type="2d"` 都能直接调用。
- **网页版**：人物直接用立绘 SVG 转图片；弹窗里展示，可下载、复制邀请文字，手机上长按保存。双击打开（`file://`）时浏览器不让导出带本地图片的画布，会自动去掉 logo 重画。
- **小程序**：真机的 Canvas 画不了 SVG，所以 32 张人物图由 `node tools/render-portraits.mjs` 预先渲染成 PNG（裁到胸口、压成 128 色，共约 640KB），放在分包 `packageShare/`，不占主包。卡片页用系统的图片分享菜单（`wx.showShareImageMenu`：发给朋友 / 保存 / 朋友圈），旧版本退回保存到相册；转发给好友时用另画的 5:4 封面当卡片图。
- **小程序码**：在小程序后台「工具 → 生成小程序码」下载后放到 `miniprogram/img/qrcode.png`，把 `packageShare/card/card.js` 顶部的 `QR` 改成 `"/img/qrcode.png"`，海报右下角就会画出来；网页版放 `demo/img/qrcode.png` 即可自动画上。

## 9. 手机横屏（小程序 + 网页版）

视觉小说本来就是宽屏的体裁，网页版在电脑上是 16:9 舞台。手机横过来以后高度只有 360–430px，电脑的宽屏布局放不下，小程序和网页版用同一套横屏布局：

- **网页版**：`style.css` 里 `@media (orientation: landscape) and (max-height: 500px)`，规则和小程序 `.stage.land` 一一对应。浏览器不能替用户转屏（iOS Safari 不支持锁定方向），所以没有「横屏」按钮，只在手机竖屏第一次进舞台时提示一次"横过手机，舞台更大"（`vn.js` 的 `rotateHint`）。
- **有选项时**：对话框让到左半边，选项占满右半边的高度（冲动选择有 4 个选项也放得下），地点条先收起来。

小程序的做法：

- **故事页、练习关页允许旋转**（页面配置 `pageOrientation: "auto"`），首页、测试、结果等阅读型页面保持竖屏。手机横过来 → `onResize` 重新计算尺寸（`core/lay.js` 返回 `land`），舞台切到横屏布局。
- **横屏布局**（`templates/stage.wxss` 末尾 `.stage.land`）和网页版宽屏一致：立绘站满舞台（高 92%），对话框压在腿上、左右收窄；选项面板挪到右半边，不挡住说话的人；手机界面、教练卡、地点牌靠右，旁白框靠左；左右让开刘海安全区。
- **HUD 上有「横屏 / 竖屏」按钮**：基础库里有 `wx.setPageOrientation` 就直接切换；没有（这个接口官方文档没写）就弹窗提示"把手机横过来，没反应请关闭竖排方向锁定"。第一次进舞台时会提示一次"横过手机，舞台更大"。
